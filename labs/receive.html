Module: Receive

Thanos Receive

Thanos Receive implements the Prometheus Remote Write API. It accepts incoming time series data, stores it in a local TSDB, and eventually uploads TSDB blocks to object storage.

It is designed to be highly available and horizontally scalable, routing incoming series to specific nodes based on a Hashring.

Deep Internal Working

When a request arrives, the Receive router looks at the labels of the incoming series. It hashes the labels and uses a consistent hashing algorithm to determine which Receive node(s) should store the data.

If replication is configured, a single series is written to multiple nodes simultaneously. Each node maintains its own local Prometheus TSDB.

Configuration Playground

  • --receive.replication-factor: Determines how many nodes a single series is written to. High replication increases durability but uses more storage and network.
  • Hashring Topology: Simulates adding or removing nodes. Consistent hashing minimizes the amount of data that needs to be "reshuffled" when topology changes.

Guided Examples

Example 1: Basic Routing

Goal: Observe how series are routed based on consistent hashing.

  1. Set Replication Factor to 1.
  2. Click "Send Remote Write" multiple times.
  3. Observation: Notice how different series (represented by different colors/hashes) are deterministically routed to specific nodes on the ring.

Example 2: Replication & High Availability

Goal: See how data survives node failure.

  1. Set Replication Factor to 2.
  2. Send a Remote Write. Observe that the request fans out to TWO nodes on the ring.
  3. Click a node on the ring to simulate a failure (toggle down).
  4. Send another Remote Write. The router will bypass the down node and find the next available nodes in the ring to satisfy the replication factor.

Failure Modes

  • Write Amplification: High replication factors cause significant network traffic and disk usage on Receive nodes.
  • Out of Quota / Disk Full: If a local TSDB fills up before blocks are uploaded and truncated, writes will fail.
  • Hashring Imbalance: If labels aren't distributed evenly, some nodes may become hotspots.
