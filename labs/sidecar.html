Module: Sidecar Internals

Thanos Sidecar

Prometheus is a highly efficient local monitoring system, but it is not designed for durable long-term storage or global cross-cluster querying. Thanos Sidecar solves this by acting as the bridge between Prometheus and the Thanos ecosystem.

What is the Sidecar?

The Sidecar runs as a companion process alongside Prometheus. Crucially, it shares the same TSDB data directory. It does not store data independently. Instead, it serves two distinct, critical roles:

  1. StoreAPI Provider (Read Path): It implements the gRPC StoreAPI on top of Prometheus's HTTP remote-read. This makes Prometheus look like a native Thanos data source. When Thanos needs recent/live data, it asks the Sidecar.
  2. Block Uploader (Write Path): It watches the local TSDB directory. When Prometheus finishes writing a ~2-hour block to disk, the Sidecar uploads it to Object Storage for long-term retention.

The 2-Hour Upload Rule (Crucial)

A common misconception is that Sidecar uploads real-time metrics. It does not. Sidecar only uploads completely cut, immutable TSDB blocks (typically every 2 hours). Live, in-progress data (the Head Block) is served to queries via the StoreAPI, not from Object Storage.

External Labels: The Absolute Requirement

Prometheus must be configured with external_labels (e.g., cluster="prod-eu1", replica="0"). Sidecar injects these labels into the metadata of uploaded blocks and StoreAPI responses. Without these labels, Thanos cannot deduplicate data or identify where metrics came from, and the system will logically break.

Storage & Compaction Requirements

Because Sidecar uploads blocks to global storage, Prometheus local compaction must be disabled (or heavily constrained). If Prometheus compacts blocks locally after Sidecar uploads them, Thanos will encounter corrupted or overlapping data in object storage. By default, Prometheus cuts blocks every 2 hours; Sidecar relies on this exact cadence.

Mental Model

  • Prometheus: Produces data, holds live metrics in RAM (Head).
  • Sidecar: Bridge + Uploader + API Layer.
  • Object Storage: Boundless long-term storage.

Real-World Behavior & Failure Modes

  • Sidecar Crashes: Prometheus keeps scraping. Blocks accumulate locally. When Sidecar restarts, it resumes uploading the queued blocks.
  • Object Storage Down: Same as above. Blocks wait on local disk until the connection is restored.
  • Missing External Labels: Sidecar will refuse to start or refuse to upload blocks to prevent data corruption.
