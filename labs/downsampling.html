Thanos Downsampling

Downsampling reduces the overall resolution of data samples without losing mathematical accuracy over long time ranges. It is handled by the Thanos Compactor.

The AggrChunk Structure

Instead of simply dropping data points, Thanos rewrites raw blocks into downsampled blocks using an AggrChunk. For each interval, it stores: 

message AggrChunk {
  int64 min_time = 1;
  int64 max_time = 2;
  Chunk raw     = 3;
  Chunk count   = 4;
  Chunk sum     = 5;
  Chunk min     = 6;
  Chunk max     = 7;
  Chunk counter = 8;
}

This allows accurate results for large duration range queries (using sum, min, max) without fetching millions of raw samples.

Downsampling Passes

Downsampling happens in two passes by default:

  1. Raw to 5m: Applied to blocks older than 40 hours.
  2. 5m to 1h: Applied to 5m blocks older than 10 days.

Example: 30s to 5m to 1h Conversion

Assume Prometheus scrapes a target every 30 seconds.

  • Raw: In 5 minutes, you collect 10 raw samples.
  • 5m Pass: The Compactor groups these 10 samples into a single AggrChunk. It calculates the sum, min, max, and sets count to 10. The 10 raw data points are mathematically represented by this one chunk.
  • 1h Pass: Later, twelve of these 5-minute AggrChunks (covering 60 minutes) are merged into a single 1h AggrChunk. The new chunk has a count of 120 (12 * 10), and new max/min/sum aggregates.

Storage Trade-offs

Downsampling does not save disk space. It creates 2 more blocks for each raw block (a ~3x storage increase). The goal is to provide fast "zoom out" query capabilities, not to compress data. If you want to save space, use Retention policies.
