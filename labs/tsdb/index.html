What is this topic?

Prometheus stores metrics in blocks. Inside each block, the index file acts like a map. It helps Prometheus answer a query such as {job="api-server", env="prod"} without scanning every chunk file from start to finish.

The goal of this track is simple: understand how Prometheus starts at the last 52 bytes of the index file and ends up reading the exact byte offset of the right chunk.

Why this matters

1
Queries need a fast lookup path
The index is what turns label matchers into a small set of candidate series.
2
Chunk bytes are expensive compared to metadata
Prometheus stores chunk time ranges in the index so it can skip chunk files until it really needs them.
3
Thanos depends on the same ideas
Store Gateway, compaction, and remote reads all depend on understanding block and index structure.
