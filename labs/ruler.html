Thanos Ruler

The Thanos Ruler evaluates Prometheus recording and alerting rules against a chosen Query API (Thanos Querier). Unlike a normal Prometheus server, it evaluates rules across the global, centralized view provided by Thanos Query, avoiding isolated "siloed" alert evaluation.

Deep Internal Working

When Ruler evaluates a rule group, the following happens:

  1. Query Execution: It sends a PromQL query via HTTP/gRPC to the configured Query nodes.
  2. Evaluation: Based on the results, it computes the recording rule (new timeseries) or determines if an alert condition is met.
  3. Stateful Storage (Default): The evaluation results are written back to its own local TSDB (in Prometheus 2.0 format). Like a Sidecar, the Ruler then exposes a StoreAPI and eventually uploads these blocks to Object Storage.
  4. Stateless Storage (Remote Write): Alternatively, Ruler can skip a local TSDB entirely and use Remote Write to stream the results to a remote storage system (like Thanos Receive).
  5. Alerting: If alerts fire, it sends them to the configured Alertmanagers.

Failure Modes & Troubleshooting

  • Evaluation Delay: prometheus_rule_group_last_duration_seconds > prometheus_rule_group_interval_seconds. Means Querier is too slow to evaluate the rule in time.
  • Alert Drop: thanos_alert_sender_alerts_dropped_total > 0. Ruler cannot reach Alertmanager.
  • Partial Response: If Querier misses some stores, Rule evaluations might use incomplete data and trigger false alerts.
