Module: Compactor

Thanos Compactor

The Compactor applies the block compaction procedure of Prometheus' local TSDB to object storage. It is responsible for:

  • Compaction: Merging multiple small blocks (e.g., 2h) into larger ones (e.g., 8h, 2d, 14d) to improve query performance and reduce index size.
  • Downsampling: Creating 5m and 1h resolution blocks from raw data to speed up long-range queries.
  • Retention: Deleting blocks once they exceed configured retention policies.

Deep Internal Working

Compaction operates on groups of blocks. By default, it groups by a resolution and specific external labels. It requires a singleton instance per bucket to avoid race conditions.

The merging process reads the chunks and index of overlapping blocks, deduplicates series, and writes a new meta.json along with the combined data.

Not documented officially: Exact internal memory footprints during compaction spikes, though it's known to be memory intensive.

Configuration Playground

Use the controls on the right to simulate Thanos Compactor arguments.

  • --wait: Run continuously. Without this, the compactor runs once and exits.
  • --downsampling.disable: Skips creating 5m and 1h blocks.
  • --retention.resolution-raw: How long to keep raw (0s) blocks.

Guided Examples

Example 1: Basic Compaction

Goal: See how Thanos groups small blocks to reduce overhead.

  1. Click "Ingest: Generate 2h Raw Block" exactly 4 times. You will see four 2h blocks appear in the bucket.
  2. Click "Run Compaction Cycle".
  3. Observation: The engine scans the bucket, identifies the four overlapping 2h blocks, and merges them into a single, more efficient 8h block. This reduces index size and speeds up queries.

Example 2: Downsampling in Action

Goal: Understand how long-term data queries are accelerated.

  1. Ensure you have at least one 8h block (complete Example 1).
  2. Ensure "Enable Downsampling" is checked.
  3. Click "Run Compaction Cycle" again.
  4. Observation: The compactor processes the 8h block and generates a secondary block with 5m resolution. Queries covering a month of data will now use this smaller, less granular block instead of parsing millions of raw data points.

Example 3: Data Retention Limits

Goal: Observe how Thanos deletes old data.

  1. Set "Retention Raw" to 24h.
  2. Click "Ingest" several times. In this simulation, each ingestion advances time by 2 hours.
  3. Click "Run Compaction Cycle".
  4. Observation: The compactor checks block timestamps. Any raw block older than 24h will be purged, saving storage costs.

Failure Modes

  • Halted Compaction: If the compactor encounters malformed blocks, it halts and produces a compaction.err.json file to avoid corrupting data.
  • Concurrency Issues: Running multiple compactors on the same bucket leads to overlapping blocks and query failures. Always use a single compactor.
  • OOM (Out of Memory): Compacting very large blocks requires significant memory. Watch your metrics!
